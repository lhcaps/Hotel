## Current authority paths

### ADMIN authentication and authorization

`/admin/login` → `apps/web/src/app/admin/login/page.tsx` → Better Auth email sign-in via `apps/api/src/auth/auth.controller.ts` → `apps/api/src/auth/auth.providers.ts` session reader → `apps/api/src/auth/admin-session.service.ts` → `apps/api/src/auth/admin-permission.guard.ts` → `apps/api/src/admin/admin.controller.ts` (`GET /api/v1/admin/me`) → `apps/web/src/lib/admin-session-server.ts` → `apps/web/src/app/admin/(protected)/layout.tsx` → `apps/web/src/components/admin-navigation.tsx`.

The current effective permission map is in `packages/auth/src/permissions.ts`. Active memberships are read from `packages/database/src/schema.ts` (`admin_memberships`, `admin_departments`); before ADMIN V2, `apps/api/src/auth/auth.providers.ts` falls back to the legacy `users.role` when no membership exists. ADMIN V2 removes that broad fallback for effective access and keeps unassigned legacy ADMIN accounts fail-closed.

### Mutation flow

UI action → `apps/web/src/lib/admin-api.ts` request → controller `@RequirePermissions` metadata → `AdminPermissionGuard` session/account/membership/profile check → service transaction → scrubbed `audit_events` append → refreshed server-authoritative response. Existing catalog mutations use `apps/api/src/catalog/catalog.service.ts` and `catalog.repository.ts`; booking lifecycle and reconciliation remain the authoritative P0 paths and are not redesigned.

## Route classification

All listed pages have an existing Next.js route. None is a missing route. They are classified as `incomplete` until the ADMIN V2 acceptance rows are independently verified. `/admin/accounts` and `/admin/customer-accounts` are a duplicated account surface; `/admin/rooms` and `/admin/room-operations` are distinct and must remain distinct (physical inventory vs operational state). No unused ADMIN route was found in the current App Router tree; route-permission coverage must still be generated from server metadata rather than sidebar visibility.

## Required ADMIN V2 route contract

- `SUPER_ADMIN`: all listed routes and mutations, subject to server permission metadata.
- `ROOM_STATUS_VIEWER`: `/admin/room-operations` and `/admin/profile` only; all other protected routes redirect to room operations and APIs return 403.
- `CUSTOMER`: never enters the ADMIN shell; authenticated access to ADMIN APIs is denied.
- Anonymous/expired session: ADMIN API 401 and protected web redirect to `/admin/login`.
