# Phase A correction risk register

## Current B0 disposition

The following risks were explicitly covered by the local hardening pass: exact
pricing coverage and deterministic ranking, full-interval same-room
availability, one-aggregate HOLD/booking/payment, whole-booking cancellation
with immutable snapshots and access revocation, final-only turnover, signed
payment callback authority, and preserved V1/RBAC behavior. Remaining scope is
listed as deferred below; it is not silently claimed as implemented.

| ID  | Risk                                                              | Severity | Evidence/impact                                                                                                                   | Mitigation and forward fix                                                                            |
| --- | ----------------------------------------------------------------- | -------- | --------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| R1  | UI allows a multi-night interval while server still rejects it    | Critical | Fixed overnight presets, `isSupportedOvernightWindow`, `OVERNIGHT_ONE_NIGHT`, and 1,440-minute pricing cap are independent paths. | B0.1-B0.3 contract-first; server exposure before UI; remove copy last.                                |
| R2  | Pricing components have a gap/overlap/double charge               | Critical | Current schema supports one base plus extra line only.                                                                            | Exact half-open union validator, catalog permission, deterministic candidate tests, fail closed.      |
| R3  | Room is free only for part of stay                                | Critical | Full interval query exists, but multi-night cases are untested.                                                                   | Middle-night booking/maintenance integration tests and exclusion/transaction locks.                   |
| R4  | Same stay is represented by multiple bookings                     | Critical | Current shape could be misused by a nightly UI.                                                                                   | One quote->one HOLD->one booking contract and explicit no-split tests.                                |
| R5  | Existing quote/booking is repriced                                | Critical | New optimizer could accidentally recalculate on read.                                                                             | Immutable JSON snapshots, old snapshot adapter, no reissue in detail/payment paths.                   |
| R6  | Payment/browser return confirms state                             | Critical | Provider returns coexist with verified callbacks.                                                                                 | Keep return controllers 204/read-only; IPN/webhook only settlement authority.                         |
